Troubleshooting
===============

SED input rejected
------------------

``method = sed`` and SED-specific parameters are no longer supported. Run SED
calculation, plotting and fitting with pySED. MDtrace does not convert old SED
inputs or change existing SED output files. With no filename, it reads only
``input.in``.

Trajectory and Q points
-----------------------

* Set ``trajectory_read_mode = cache`` for DSF text input. The direct text
  readers remain available in the Python I/O modules, but the DSF workflow
  requires NetCDF or a converted cache.
* A missing or outdated MDtrace cache can be regenerated by supplying the
  original text trajectory. Do not rename an old cache to bypass validation.
* Current spectra require saved velocities. Density DSF can use positions alone.
* Cells must be fixed and fully periodic. ``dsf_cell`` can supply missing cell
  data, but cannot override a different cell stored in the trajectory.
* Explicit Q vectors must be commensurate with the simulation cell. Use the
  crystal path or spherical sampling options for automatic allowed points.
* ``time_step`` is the MD integration step in fs; ``output_data_stride`` is the
  number of integration steps between saved frames.

Outputs and statistics
----------------------

``action = plot`` requires complete spectrum, frequency and Q-axis text files. ``thinking`` checks
the input settings and source signature before reusing numerical results.
Explicit ``compute`` always recalculates; explicit ``plot`` always redraws.

A single block cannot estimate SEM, so its SEM is NaN. A sparse Q-shell warning
indicates limited directional coverage, not a calculation failure. Current
spectra are undefined at Q=0 and contain NaN there. See :doc:`dsf_workflow` for
normalization and convergence checks. ``device = gpu`` requires CuPy and a
usable CUDA device. GPU frame/Q batches adapt to available memory; atom-wise
outputs still require a complete atom-wise block to fit device memory.
Automatic peak fitting is not implemented.
